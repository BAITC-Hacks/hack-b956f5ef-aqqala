## Часовой пояс: данные в UTC+6, без сдвига
Искал сдвиг, при котором прогноз погоды лучше всего совпадает с измерениями:

| Сравнение | Лучший сдвиг |
|---|---|
| Ветер против GFS | UTC+6:00 |
| Ветер против ECMWF | UTC+6:00 |
| Ветер против ICON | UTC+5:30 |
| Температура (три модели) | UTC+6:10…6:50 |
| До и после 01.03.2024 | одинаково, скачка нет |

**Вывод:** метки времени всё время в UTC+6 (старое алматинское время). Смену пояса в 2024 SCADA не подхватила. Решение:
- внутри системы всё храним в UTC;
- исторические данные переводим как «время − 6 ч»;
- пользователь вводит дату и время в UTC+6 (как в данных), вывод тоже в UTC+6.

## Previous Runs API: что реально доступно
| Модель | Прогноз на сегодня (day0) | На 1–2 суток вперёд (day1/day2) | Ветер 80/120 м |
|---|---|---|---|
| GFS | с 2023 | **с 16.02.2024** | есть |
| ICON | с 2023 | **с 16.02.2024** | есть |
| ECMWF IFS | с 06.03.2024 | **с 07.03.2024** | нет, только 100 м |
| MeteoFrance, CMA | с 2024 | нет | — |
| GEM, JMA, UKMO | нет | нет | — |

**Что это значит:**
- **Обучение на честных прогнозах возможно только с февраля 2024.** Это ~23 месяца, включая две зимы, этого хватает. Ранние данные (с 2023) годятся только для кривой мощности.
- **Правило без утечки:** прогноз выпущен в момент T, целевой час T+h. Для h ≤ 24 берём `previous_day1`, для 24 < h ≤ 48 берём `previous_day2`. Так используются только прогнозы, которые уже существовали в момент T.
- **Прогноз погоды совпадает с фактом неидеально**, корреляция ~0.75. Значит, связка из трёх моделей (GFS + ICON + ECMWF) и ML-коррекция действительно дадут выигрыш.

## Как учёл ваши требования

| # | Требование | Решение |
|---|---|---|
| 1 | Previous Runs API | Три модели: GFS, ICON, ECMWF. Переменные: ветер на 10/80/100/120 м, направление, порывы, температура, влажность, давление |
| 2 | Ввод даты и времени | `forecast --issue "2026-02-01 10:00"` → 48 почасовых строк |
| 3 | Часовой пояс | UTC+6 фиксированный, внутри всё в UTC |
| 4 | Турбины и итог | Колонки T1, T2, … и итоговая: **средняя доля** по ВЭС (сумма долей здесь не имеет смысла). Новая турбина = строка в `turbines.yaml` с координатами |
| 5 | Кеш | Один скрипт скачивает архив прогнозов в `data/weather/*.parquet`. Прогноз работает только из файлов, без сети |

**Новая турбина без своей истории:** берём её прогноз погоды по её координатам и общую модель парка. Своя история, если появится, потом дообучит модель.
